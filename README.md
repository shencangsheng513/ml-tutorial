| [ml-toolcall](ml-toolcall/) 小模型函数调用·负结果合集 | minimind 30M（hidden 512）+ 8 个 mock 工具 | 四种数据侧修法全部证伪（契约 A/B p≈0.61、扩容 2.3x 反退化、对抗样本逐字同分）；规模对照线 12→21→24/24 定位天花板=预训练先验 | **负结果怎么升级成结案**：加样本杀噪声、结论带适用范围、复现的"同分"同时是药方无效和仪器可信的证据；止损决策表 |

## 跨项目方法论（踩出来的）

1. **泄漏是头号公敌**：时间泄漏/元数据泄漏/评估泄漏，每个项目用对照实验量化一次
2. **指标反常 = 流程警报**，先审计后庆祝（时序课因此发现多步预测标签泄漏）
3. **误差分析决定投资方向**：分片、混淆对、置信度分层收益 > 换模型
4. **train/serve 一致性**：一套预处理从训练用到线上（增强不对齐分布时是毒药，有实验）
5. **上线三件套**：置信度阈值 + 输入护栏 + 拒答转人工
6. **评估工具也是被测对象**：RAG 首轮输给裸考，查出的问题是提示词和判卷官自己；judge 全给满分是量表饱和，不是完美
7. **墙钟数字必须先量仪器自己的分辨率**：同一份权重测两遍当对照臂，噪声底压不住差异就不许下结论；"一臂跑完再跑下一臂"能漂 4.3 倍，同进程交错配对能压到 1.15 倍——坏的是估计算法，不是延迟这个指标。六条追加：**底要按各臂自己的量级重算**（读数的最小刻度在 0.015 ms 量级上自己就占 6.7%，拿老师的百分比套学生=假过闸）；**拟合式不许跨架构外推**，要在训练前把它写成可打的数字当预测（ml-compress 第4课：0/6 命中、误差 −83%~−85%，那条"上界"属于那副图不属于机器）；**"再跑一遍"不等于复现**——固定种子下重跑逐位复现，量不到种子方差，误差棒必须由真正产生它的那个随机源给（换随机流 / 换机器状态 / 换进程是三种不同的方差。ml-compress 第4课b：换 3 条随机流重训后，满数据"蒸馏有害"扛住了、低数据那点好处被降级）；**拟合出来的"物理上限"报成带、不报成点**（同配置跑到 5 次，固定开销的跨度从 5.3pp **涨**到 5.8pp——带宽是当轮机器状态传导进截距的，加样本量救不了；跨运行真正稳的只有同轮比率，极差 2.8%）；**对照臂的统计量要先证明不退化**（ml-compress 第4课c：配平臂每个温度只有一个 α，"跨 α 极差"按构造恒为 0，第一版于是打印出"配平后 T 轴被压平 ⇒ 原假说借温度复活"这个反向结论，改成"钉回梯度换回多少伤害、与种子底比"才拿到正确判决——能算出 0 的差值不等于没有差；顺带一条：零训练探针推翻实验自身前提（α 与 T 并不正交）时，正确动作是照它改设计，不是沿用旧假说的措辞收尾）；**加参数开关必须档案驱动**（ml-compress 第4课c 加 `--width 64`：锚点档案值、H1 的伤害基数、种子底三样全部从该宽度自己的 `compress_report_v4b*.json` 读，并加 `width` 字段闸门，拿错档案就直接报错退出而不是回落到默认字面量——多写一套字面量就等于多装一个会悄悄说谎的对账栏，逐位对账闸门一绿人就停止怀疑了）；**跨架构迁移 ≠ 独立复证**（换宽度重扫测的是"这条结论绑不绑架构"，两副学生仍共享同一个老师、同一批数据、同一份软标签，数据那侧的独立性要换 teacher 才拿得到；所以判词要写在自己的适用范围内："在这台机器上、这一副学生上"，而不是一句"蒸馏无用"）

## 快速开始

```bash
pip install -r requirements.txt
# 每个项目目录内按 README 运行；App 均为 Streamlit，各带 launch_*.bat
```

- 3 个 Streamlit 应用端口：8502（时序）/ 8503（文本）/ 8504（手绘数字）
- MLflow UI：`python -m mlflow ui --backend-store-uri sqlite:///mlflow-lab/mlflow.db --port 5000`
