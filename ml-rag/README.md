# ml-rag — 给教程仓库装一个"问答大脑"

把本仓库 9 篇 md 文档建成向量索引，用 RAG 回答"我在这个教程里到底做过什么"，并用 **LLM-as-judge** 对照"有资料 vs 裸考"的答题质量。呼应路线图：BERT（第8课）解决词序，本课解决"知识外置"。

## 架构
```
build_index: md → 标题感知切块(chunker) → 嵌入(embeddings,带磁盘缓存) → 余弦向量库(store)
ask:         问题 → 嵌入 → top-k混合检索(向量+BM25,RRF融合) → 拼进prompt → LLM作答(带引用出处)
run_eval:    13题三层评估（见下）
```
> 检索默认走 hybrid（90 题大盘 top-4 命中 87.8% vs 纯向量 81.1%）；`ask.py --vec` 回退纯向量。

## 三层评估方法（这是本项目的主角，不是能聊天就完事）
| 层 | 指标 | 成本 |
|---|---|---|
| L1 检索命中率 | top-4 里有没有标准答案所在文档 | 零（本地向量算） |
| L2 有/无上下文 | 同 13 题各答一遍 | 生成费 |
| L3 LLM-as-judge | 按"事实/覆盖/可操作"三维 0-10 打分；**奇偶交换A/B位置防位置偏置**；judge 有标准要点当依据 | 评分费 |

## 实测结果：两轮迭代（评估驱动开发的活教材）
| 版本 | 检索命中 | RAG 均分 | 裸考均分 | 胜/平/负 |
|---|---|---|---|---|
| v1 | 13/13 = 100% | 6.69 | 8.00 | 5/0/8 ← RAG 输了 |
| v2 | 13/13 = 100% | 10.00 | 3.23 | 13/0/0 |

v1 检索全中但答题反而输给裸考，复盘定位到两处提示词问题：
1. **生成端自己把模型吓住了**："只根据资料回答，没有就直说不知道" → RAG 答案变成资料片段的干巴巴复述；改成"关键数字必须出自资料且一字不差，在此前提下像讲课一样充分展开"后立竿见影。
2. **判卷端纪律不足**：judge 凭自己记忆加"标准答案"（把 65.8% 判成"应该是 77%"），逼着模型用外部知识答题；加上"只按标准要点核验、不许引入要点外数字"的判卷纪律后收敛。

**v2 的 13 连胜也要打折看**：RAG 全部恰好 10.0 是分数饱和（天花板效应），抽查一道题的生成发现模型把资料里没写的护栏细节也推理得斩钉截铁——真实分数应在 8-9。结论：修复方向是对的、差距是真的，但**判卷官本身也需要校准**（更细的量表或强制扣分点），指标是工具不是真理。

## v3：把"判卷官可信吗"和"检索还能更好吗"做成实验
v2 留下的两个疑问，v3 用数据回答（产物在 `evaluation/`，重跑全部走缓存）：

**① 判卷官校准——它真的有牙吗？**
- 锚定量表（8 起评、漏要点 −2、编造 −3）+ grounded 规则（把原始资料给 judge，每处无据断言 −2）重判 v2 全部 13 题：仍是 13/13×10 → v2 的满分是真实力，不是判卷放水。
- **敏感性探针**：往 3 题已知优秀的回答里人为注入错误（改数字 / 加资料里没有的断言），judge 3/3 抓到（−4/−2/−4）。但其中一题只抓到改数字、漏了编造的 Redis 断言 → **判卷官对数字敏感 > 对虚构声明敏感**，这是残余盲区。
- 多跳 e2e 里量表真正咬人：M3 的 RAG 答案因"漏 1 要点 + 1 处编造数字"被当场判 6。

**② BM25 混合检索（RRF 融合）——加了混合一定更好吗？**
- 23 题 hit@4：纯向量 / 纯 BM25 / 混合全部 100% —— **饱和指标没有区分度**，换 MRR@6（第一名平均位次倒数）才看出差异：

| 题组 | 纯向量 | 纯 BM25 | 混合 RRF |
|---|---|---|---|
| 单跳 13 | 0.769 | 0.808 | 0.692 ← 混合反而垫底 |
| 压力 6（精确 token vs 零重叠转述） | 0.708 | 0.750 | **0.917** |
| 多跳 4（答案跨两篇文档） | 0.438 | 0.438 | 0.438 |

- 三个诚实结论：单跳上 RRF 稀释了"两榜第一同名"的共识（混合不是万能药）；压力题（精确型号/数字）才是混合的主场；**多跳全方法同分**——第二篇文档埋得太深，检索层修不动，真正需要的是查询分解（下一步）。RRF 的 c 参数 10~60 不敏感，c=5 略差。
- **23 题太少，扩容 90 题大盘验证**（`scripts/build_stress.py` 让 LLM 按每篇文档出短题，`evaluation/stress_recall.py` 只花嵌入费）：top-4 命中率纯向量 73/90（81.1%）vs 混合 79/90（87.8%）——小样本饱和时看不见的差距，样本量上去后混合检索的真实增益显形（+6 题，都是精确 token 类）。

**教训一句话**：无区分度的评估证明不了任何东西——hit@4 满分时以为赢了，换上 MRR 才发现三个方法在摸高同一块天花板。

## v4·检索线：多跳查询分解——把 0.438 打上去，然后被打回来再想明白
v3 遗留：多跳题全方法 MRR@6 同分 0.438，检索层修不动，指向查询分解。做法（`src/rag/decompose.py`）：LLM 把问题拆成 ≤3 个子问题 → 每个子问题走 v3 的 hybrid 检索 → **两种融合策略 A/B**：
- reserve（槽位保证）：每个子查询的 top-1 先占一个结果槽位，剩余按 RRF 补满；
- plain（纯多查询 RRF）：所有子查询榜单直接融合，不做保证。

4 题老题集没有区分度（同方法重跑 MRR 都能从 0.438 漂到 0.500——n=4 就是抛硬币），于是用 LLM 按文档对**生成 20 道新跨文档题**（`scripts/build_multihop20.py`，题面自带数字锚点）做 L1 大盘：

| 方法（n=20 多跳） | MRR@6 | 双文档全进 top-4 |
|---|---|---|
| 直接 hybrid（v3 冠军） | 0.401 | 16/20 |
| **分解 + 槽位保证** | **0.439** | **17/20** |
| 分解 + 纯多查询 RRF | 0.215 | 8/20 |

三个发现：① 分解确实能把第二跳的文档从深埋里捞出来，但增幅温和（+9%），有 2 题三臂全灭（题面引用了索引里确实没有的信息，检索层无罪）；② **真正的坑是"朴素平均"**——子查询榜单直接融合时，两跳都会命中的近端块重复加分上浮，把远端块挤出 top-6，指标腰斩；③ 分解版的端到端判卷 3:1 占优（26 vs 22 分），但 n=4 仍不足为凭。产物：`evaluation/multihop20_ab_v4.json`、`decompose_ab_v4.json`（4 题 e2e 明细）。

**v4 教训**：加一个"看起来正确"的组件（查询分解）时，消融它的实现变体（reserve vs plain）和样本量（4→20）比组件本身更重要——两个变体差出一倍，说明机制细节才是结论的主人。

## v5：把 v4 检索线拉到 50 题复验——+9% 被打回原形，腰斩活了下来
v4 自己留的口子（"n=20 够不够"）由 v5 回答。`scripts/build_multihop50.py` 扩到 50 题：10 篇文档只有 45 对，老题沿用原缓存键零成本续跑，缺的 5 题用"换比较角度"的第二轮生成。三臂重测 + 对 reserve-vs-hybrid 逐题比最差名次做**双侧符号检验**：

| 方法（n=50 多跳） | MRR@6 | 双文档全进 top-4 |
|---|---|---|
| 直接 hybrid | 0.3845 | 30/50 |
| 分解 + 槽位保证 | 0.3926 | 33/50 |
| 分解 + 纯多查询 RRF | **0.2593** | 19/50 |

- **v4 的"+9%"没扛过复验**：50 题上 reserve 仅 +0.008（+2%），胜负盘 12:11、平 27，p=1.000——统计上与抛硬币无异。n=20 时那 +9% 是小样本噪声的可能性远大于真实增益。
- **v4 的"plain 腰斩"是真机制**：50 题上依旧塌（0.26、19/50），近端共识块挤掉远端块的因果解释继续成立。
- **结论修订**：查询分解在多跳上的价值目前**未被证明**——它修不动的东西比 v3 说的更多（连检索层的"覆盖保证"都换不来名次）。方向不是错，但按本仓库纪律：增益测不出来就不配进主流程，`retrieve_decomposed` 保持实验代码，`ask.py` 默认路径不变。
- 方法论增量：**A/B 差两个点以内时，20 题不够看，要给符号检验兜底**（`run_multihop50_ab.py` 里 20 行纯 python 的精确二项检验，无 scipy）。产物：`evaluation/multihop50_ab_v5.json`。

**v5 教训**：证伪自己的最新结论，比证实它更有价值——v4 的"n=4 是抛硬币"警觉是对的，只是 20 也没到终点线。

## v4·判卷线：判卷官换两把尺子，饱和终于解除
v3 的残留问题：配对判卷（L3a）在没有原始资料时只能核对"标准要点"，对"要点全中但顺手编了十个细节"的答案睁一只眼闭一只眼——17 题里 RAG 答案仍是大片 10 分。v4 把判卷拆成两个正交指标：

- **L3a 配对分**（对称，无资料）：A/B 两组同罪同罚，先列事实清单（每条断言 ✓/✗）再锚定打分（8 起评、漏要点 −2、✗ −3）。
- **L3b 有据性分**（只判 RAG 组）：把检索到的【原始资料】全文给判卷官，每处"资料没写但说得斩钉截铁"的断言 −2。裸考组天生要用外部知识，不参与此项——**不对称的公平才是公平**。

17 题（13 单跳 + 4 多跳）双指标终评：

| 指标 | RAG | 裸考 | 胜/平/负 |
|---|---|---|---|
| L3a 配对（RAG vs 裸考） | **8.94** | 2.41 | 16/0/1 |
| L3b 有据性（仅 RAG） | **8.94**（无据断言共 20 处） | — | — |

量表真正咬人的三处证据（不再是清一色 10）：
1. 一道多跳题 RAG 输给裸考（4 vs 6）：两篇文档只检索到一篇，有据性也只有 4.0（7 处无据断言）——**与 v3"多跳是检索层修不动的短板"的 MRR 结论互相印证**，指标之间不打架。
2. 一题配对满分 10、有据性当场 6.0（5 处无据断言）：要点全中但护栏细节是自己脑补的——这正是 v3 探针预警的残盲区（配对判卷抓得住改数字、抓不住编断言），L3b 把它当场抓住。
3. 一题 RAG 判 6：覆盖了要点但把版本号写错，fact_check 里被逐条点名。

结论：RAG 对裸考的优势是真的（8.94 vs 2.41，16/0/1），但 **v2 那种"13/13 全满分"是判卷饱和的假象**；换上 L3b 之后，每一分扣在哪条断言上都能指认。判卷官经过锚定量表 + 探针校验后，现在是仓库里最贵也最可信的一件仪器——但它仍是仪器，不是真理。

## v6：分块消融——标题感知切块用了五个版本，这次让它自己交代
切块是检索链路上最后一个"从没被 A/B 过就在生产"的组件。`evaluation/run_chunk_ab.py` 三策略公平对照（只差"怎么切"，嵌入与 hybrid 链路参数与 `ask.py` 全同）：

| 策略 | 块数(中位字) | 90题 hit@4 | MRR@6 | 50题多跳双文档进top-4 |
|---|---|---|---|---|
| A 标题感知·700（生产基线） | 53 (439) | 0.856 | 0.746 | 30/50 |
| B 定窗 700·砍掉结构 | 38 (700) | 0.889 | 0.772 | 31/50 |
| C 标题感知·细到350 | 86 (268) | 0.889 | 0.705 | 27/50 |

- B 在文档级 hit@4 上略占先，但**多跳口径（双文档全进 top-4）专门挤这种"大块覆盖宽"的水分**——挤完就平了。逐题符号检验：B vs A 压力题 15:8（p=0.21）、多跳 12:11（p=1.00）；C vs A 多跳 8:16 方向上亏给基线但 p=0.15。**没有任何一格过显著性线**。
- 结论：这个规模的小语料上，分块策略对检索的影响**低于 n=90+n=50 的检测力**。A 继续在岗的理由改换成诚实版——**标题感知买的是"引用可归因、prompt 带小节上下文"，不是检索指标**。
- 附带揪出一条工程债：当前语料重建出 53 块，生产索引还是 40 块——README 等文档本身入库、v4/v5 之后一直在改，索引早旧了（重建零 API 成本，本轮嵌入已全进缓存；因并行会话可能正拿旧索引跑评估，暂不动，记入待办）。
- **v6 教训**：饱和有第三层——不止判卷官会饱和、指标会饱和，**小语料对组件改动本身也会"测不动"**。测不动的组件别吹"设计正确"，要么给它找检索以外的岗位（如可归因性），要么把样本扩到能测动为止。

## v7：50 题多跳端到端判卷——先给金标装上"逐字引用"闸门，再让 L3a+L3b 咬真链路
v5 只测了检索层（L1），端到端一直没在多跳口径上过。这次补完，但先撞上一个硬前置：`qa_multihop50.json` 只有问题没有 gold，而判卷官没 gold 就无从判起。

**金标不能是"LLM 复述的答案"——那等于让幻觉给幻觉背书。** `scripts/build_multihop50_gold.py` 加了引用闸门：每个要点必须是语料逐字片段（按 `…` 切开后整段做归一化子串回查），回查不过就带失败片段反馈重试一轮（"逐字复制，标点都不许动"）。50 题一轮结果：**留 18 / 废 32**（25 题引文造假 + 7 题答不了）——半数以上题源自 40 块的旧索引，语料涨到 58 块后题库腐烂 64%。重试轮救回 14/25，终盘 **留 32 / 废 18（腐烂率 36%）**：引文回查失败 11 + 答不了 7。废题率本身就是产物——**题库不是一次生成永久有效，语料动一次就要重审一遍**。

**e2e**（`evaluation/run_multihop50_e2e.py`，hybrid 主路径 × L3a 配对含 parity 交换 + L3b 有据性）：

| 分组（n=32） | RAG | 裸考 | 有据性 | 胜/平/负 |
|---|---|---|---|---|
| 全部 | **8.12** | 4.25 | 8.75 | 26/0/6（符号检验 p=0.00027） |
| 检索双中 15 题 | 8.33 | 4.40 | 9.33 | 13/0/2 |
| 检索缺腿 17 题 | 7.94 | 4.12 | 8.24 | 13/0/4 |

- **RAG 增益在跨文档多跳上依然显著**——v3 说的"多跳是短板"限定在检索层名次，没传导到答案分：缺腿只比双中低 0.39，一篇文档半句话也够模型讲对方法论。
- **但败题几乎全长在缺腿里**：6 负中 4 题缺腿，且有据性最惨的两题（4.0/6.0，5 处无据断言）都是缺腿——平均不掉分，尾部风险翻倍。检索层修不动的东西，端到端会以小概率惨案的形式收利息。（**v7.1 补题库后本条被削弱**，见下）
- **乌龙一条（比判卷官噪声更有价值的发现）**：首轮分析指控判卷官"写'裸考全✗'却给 8 分"——复核发现是 **harness 自己的 bug**：parity 奇偶交换只回填了分数，reason 里的 A/B 字母没回填，奇数题读反。修回填后离线重跑全表一致性审计（reason 情感方向 vs 分差符号，纯规则零成本）：**31/32 一致**，唯一例外是 1 分差的边界题（两答案都漏要点，属判读噪声不属矛盾）。判卷官被平反，教训换了主语：**怀疑仪器之前先查记录本——"仪器噪声"有一半是转录错误**。
- 产物：`qa_multihop50_gold.json`（kept 32 + dropped 18 带死因）、`multihop50_e2e_v7.json`。

**v7 教训**：gold 抽取是评测链上最后一个没被审计的环节——加了逐字回查闸门后它第一件事就是证伪了自家题库 64%。评估体系的可信度等于其中最弱一环的可信度。

### v7.1：废题修完再测——上一节的"尾部风险翻倍"当场被削弱
废而不修只算诊断。`scripts/repair_multihop_bank.py` 给 18 道废题按原文档对在当前语料上重新出题（新缓存键，老 32 题零重付），再过同一金标闸门：**留 42 / 废 8**（腐烂率 64%→36%→16%；新 18 题里仍有 8 道出不来能过闸门的题——生成端"数字必须逐字可查"的硬规则也只能压降、压不消造假）。e2e 复跑（n=42）：

| 分组（n=42） | RAG | 裸考 | 有据性 | 胜/平/负 |
|---|---|---|---|---|
| 全部 | **8.19** | 4.19 | 8.90 | 35/0/7（p=7.5e-6） |
| 检索双中 22 题 | 8.09 | 4.23 | **9.45** | 18/0/4 |
| 检索缺腿 20 题 | 8.30 | 4.15 | 8.30 | 17/0/3 |

- 答案分的组差**反号**了（缺腿比双中还高 0.21）——v7"败题长在缺腿里"经不起 10 道新题的增量检验，n=17 的组间 ±0.4 全在噪声半径内。
- 缺腿的**稳定**效应只剩有据性（9.45 vs 8.30）：检索缺一条腿，分数不塌，塌的是"每句有出处"——缺腿引出的不是低分，是幻觉。这与 v4"有据性是唯一没饱和的指标"一脉相承。
- RAG vs 裸考的总增益复验更硬了（8.19 vs 4.19，p=百万分之七）。判卷官一致性审计复跑：42 题里仍仅 1 处 1 分差边界矛盾。
- **v7.1 教训**：修样本本身就是一种实验——补题前那句"尾部风险翻倍"说得很顺嘴，补 10 道题就碎了。**组间差小于一个点、组内 n<20 的分层结论，一律标注噪声半径再出口。**

## v8：一句提示词救不了缺腿幻觉——护栏消融的干净证伪
v7.1 剩下唯一站得住的缺陷：检索缺腿时塌的是有据性（9.45→8.30）。假设很诱人：在系统提示里加一句"资料没覆盖的部分明写『资料不足』，不要凭常识补全"就能补回来。`evaluation/run_coverage_guard_ab.py`：同 42 题、同 hybrid 检索，基线臂全走 v7.1 缓存零重付，护栏臂新调用（`answer_with_context` 为此加了实验专用的 `system` 参数，默认路径缓存键不变）。

| 组（n=42） | 有据性 基线→护栏 | 护栏胜/平/负 | p | 触发"资料不足" |
|---|---|---|---|---|
| 全部 | 8.90→9.05 | 9/27/6 | 0.61 | 6/42 |
| 双中 22 | 9.45→9.82 | 5/15/2 | 0.45 | 2/22 |
| 缺腿 20 | **8.30→8.20** | 4/12/4 | 1.00 | 4/20 |

- **主假设当场证伪**：缺腿组有据性纹丝不动（还略降），符号检验无胜负差。
- 拆开看更有意思：护栏**触发时确实止得住幻觉**——触发组无据断言 16→9 近乎砍半；但 L3b 的分数同时计"漏要点"，承认不足换来的有据性加分被完整性扣分吃掉，**净分不涨**。未触发的 36 题里断言也整体变谨慎（无据 38→23），同样没换成分数。
- 全局看：54 处无据断言 → 32 处，-41%，**但这是在模型只有 14% 的意愿承认"资料不足"的前提下**——软提示管不住"资料只有一半时它还是想把话说圆"的本能。
- **判词：护栏不进生产**（增益测不出来就不配进主流程，仓库纪律）。方向修正：缺腿幻觉的解药不在生成端措辞，在检索端补覆盖（k>4 / 分解）或输出端结构化（强制逐要点标注出处，让"没据"无处藏）——后者留给 v9 若有人接。
- **v8 教训**：消融要在"分数怎么定义"层面读——同一个干预在 violations 上有效、在 score 上无效，不是干预不行，是**量表把两个方向相反的效应加成了一个标量**。报效别只报一个数。

## v9：硬结构护栏反向证伪——"每句标出处"饿瘦了答案，但零成本归因核验器留下来了
v8 判词指向输出端结构化。`evaluation/run_cite_output_ab.py` 把提示换成硬约束：每句末尾必须挂【资料i】编号、"写不出出处的句子就不要写，宁可短不可编"。同 42 题同检索，基线走缓存。结果是被干预方**两项指标齐声判负**（这次不是量表混叠，是真的更差）：

| 组（n=42） | 有据性 基线→引用 | 胜/平/负 | p | 完整性配对 胜/平/负 |
|---|---|---|---|---|
| 全部 | 8.90→**7.57** | 5/14/23 | 0.001 | 7/0/35 |
| 双中 22 | 9.45→8.91 | 4/11/7 | 0.55 | 3/0/19 |
| 缺腿 20 | 8.30→**6.10** | 1/3/16 | <0.001 | 4/0/16 |

- 机制：句句要出处 → 模型选择少写——完整性崩（L3a 7:35），漏要点把有据性也拖下水。**缺腿组反而伤得最重**：一半句子找不到出处，"不可编"直接饿死答案。
- **但归因核验器是意外收获**：离线零成本检查"带出处句子中的数字能否在被引资料块逐字找到"，引用臂 60/75=80% 可归因——模型肯挂出处时基本不撒谎（15 句疑误挂，逐条可查）。这个检查器与 v7 金标闸门同构，可用于任何带出处输出的生产校验。
- **v8+v9 合并判词（本线结案）**：缺腿幻觉在输出端两头堵死——软提示没意愿（14% 触发），硬结构饿死完整性。生成端措辞这条路**双证伪关闭**，欠的债认给检索端覆盖，而检索端 v5 已证明查询分解修不动名次——这是诚实的负结果闭环：当前架构下缺腿有据性 -1.2 是**已知且暂无更优解**的代价，`ask.py` 维持原样。
- **v9 教训**：干预测出显著负效应同样是高价值结果——它把"看着最像解法"的路封了，还顺手留下一个可复用的仪器。负结果连报两届（v8、v9），方法线到此为止，再深挖要先换变量（检索配置/语料规模），不加钱不加题的消融已经榨干。

## v10：v9 的核验器转正——ask.py 答后附一行零费"数字查无出处"提示
生成端措辞已双证伪（v8/v9），但检测端没人试过：不改答案、不拦输出，答完之后**免费**复核一遍数字。生产答案不带逐句【资料i】标注，所以核验器改成无标注版（`src/rag/attribution.py::ungrounded_numbers`）：答案里每个数字（小数或 ≥2 位整数），若在**模型的整个输入**（top-4 检索正文 + 题面）里找不到逐字出处，就列为可疑。

- **接主流程前先在 42 题缓存答案上体检**（`evaluation/calibrate_attribution.py`，全走缓存零费）：第一版只认检索资料，45% 答案带警报，翻开一看大半是**答案复述题面自带的数字**（0.4437、0.853…）——不是幻觉，是 grounding 集少了一块；把题面纳入后降到 40%（28 个可疑数字/42 题）。
- 残留标记的构成（逐条人查）：大头是**算术派生值**（0.853−0.826=0.027、0.4437−0.4229=0.0208），字符串核验天然抓不住换算；真收获是 `1797`（digits 数据集尺寸，资料和题面里根本没有，模型从自己知识里掏的）——这正是"数字必须出自资料且一字不差"承诺的违例。
- **判词：进主流程，但以提示器身份**。措辞写死留余地（"换算/四舍五入属正常，否则请复核"），只列数字不动答案，零 API 零延迟。v9 判词"ask.py 维持原样"修正为：**生成路径原样，答后多一行免费体检报告**。
- **v10 教训**：仪器转正前要拿已知判决的样本校准误报构成——"40% 答案带警报"这个数字本身没有意义，**拆开看警报里谁是真凶谁是冤案**才有。grounding 集要等于模型的完整输入，少一块（题面）误报率就虚高 5 个点。

## v11：换变量兑现——k=6 补上了检索的腿，答案却没接住
v8~v10 把生成端措辞封死、检测端补了个免费哨兵，欠的债都认给"检索端覆盖"。那就换变量试最深的嘴：`evaluation/run_depth6_ab.py` 只改 k（4→6），同题库同 SYSTEM_RAG，k=4 基线双臂（答案+判卷）缓存预检 42/42 全命中零费，k=6 臂新调用（约 126 次）。预检先行（零费）：k=4 缺腿的 20 题里 **10 题 k=6 翻正双中**——有肉才放行付费。结果：

| 组 | 有据性 k4→k6 | 胜/平/负 | p | 完整性配对 胜/平/负 | 无据断言 | 核验器报警 |
|---|---|---|---|---|---|---|
| 全部 42 | 8.90→8.90 | 9/23/10 | 1.00 | 16/1/25 | 54→54 | 28→31 |
| 双中(k4) 22 | 9.45→9.27 | 4/14/4 | 1.00 | 9/1/12 | 17→19 | 19→17 |
| 缺腿(k4) 20 | 8.30→8.50 | 5/9/6 | 1.00 | 7/0/13 | 37→35 | 9→14 |
| **翻正 10（真受治组）** | **8.20→8.20** | 2/6/2 | 1.00 | **1/0/9** | — | 5→5 |

- **核心判决在翻正组**：腿真补上了，有据性纹丝不动，完整性 1:9（符号检验 p≈0.02）——本轮全线第一个显著的配对效应，方向是负的。多喂两条资料的"稀释"代价大于覆盖收益：模型被新增块带偏去铺陈旁支，该写的要点反而漏了。
- 机制补刀：文档进 top-6 ≠ 金标数字进上下文（整篇 README 里可能就那 3 行有用），以及"仍缺 10 题"里核验器报警 4→9——补进无关块只会诱发更多可疑数字。
- **判词：k=6 不进主流程，`ask.py` 维持 k=4**。至此四条路全部实测封死/收口：生成端软提示（v8）、生成端硬结构（v9）、检索端查询分解（v5）、检索端加深（v11）；检测端哨兵（v10）上岗。缺腿有据性 -1.2 从"暂无更优解"升级为"**在现有架构与评估仪器下，所有便宜变量均已排除**"。
- **v11 教训**：分组要看"真受治组"，大盘平均会杀疗效也杀毒药——全部组双指标"无变化"，翻正组却藏着 p=0.02 的显著伤害。消融预检（零费）不只是省钱闸门，它还预先定义了谁才是实验的观众。

## v12：语料 5 倍扩容——稀释的账单曝光了，但 hybrid 反而更值钱
v11 收官时留了一句诚实的话："方法线便宜变量已尽，剩下的都是贵变量（语料、模型）"。这一轮兑现第一个贵变量：把仓库里 54 个真实 `.py`（ml-rag 自身除外，免得把评估仪器当知识）收进知识库，语料从 76 块 → **387 块 / 194k 字符（5.1 倍）**。切块器加 `chunk_code()`：按顶层 `def`/`class`/装饰器切，前导 import 与模块 docstring 归 `(module)`，超长块按行边界二次切（代码不重叠，与散文不同）。

**三臂对照，先把混淆摘干净**（`evaluation/run_scale_stress.py`，阶段 1 全程零费——题面早嵌过、md 块走嵌入缓存）：

| 索引臂 | 块数 | 90 题 hit@4（向量/hybrid） | MRR@8（向量/hybrid） | 42 题多跳双中 |
|---|---|---|---|---|
| 生产（旧快照，建库时点早） | 58 | 70 / 78 | 0.671 / 0.760 | 22 |
| 对照（当前 md，仅文档） | 76 | 70 / 78 | 0.668 / 0.759 | 23 |
| **扩库（md + 代码）** | **387** | **46 / 66** | **0.351 / 0.538** | **14** |

- **第一跳（58→76）几乎为零**：hit@4 一模一样，双中只 +1。这条是给评估工具本身做的体检——我这几轮往 README 里追加了 v8~v11 三节，索引没重建，但**旧快照并没有拖后腿**，所以后面的跌幅不能赖给"新鲜度"。
- **第二跳（76→387）才是规模的真账单**：向量臂 90 题掉了 24 题命中（-34%），MRR 腰斩；多跳双中 23→14，**9 题翻坏、0 题翻正**。机制查得明明白白：扩库后 top-8 里 **61%~67% 的位置被代码块占据**，而这些题的金标全在文档里。
- **本轮唯一的正面发现**：hybrid 的领先幅度随规模**放大**。小语料 hybrid 比向量多 8 题、MRR 高 0.091；扩库后变成多 20 题、MRR 高 0.187。原因很直白——BM25 吃逐字命中，语义"长得像"的代码干扰物（同样是 sklearn / RMSE / TF-IDF 那套词）骗不到它的分，而向量臂恰恰被这种近似语义拖下水。**v5 收 hybrid 进主流程这条判决，在 5 倍规模下从"略优"升级为"减震器"**。
- **自我审计（这一条比结论重要）**：题集金标 100% 是 markdown，所以"加代码"对这套题**结构上只可能有害**——本轮测的是"检索在干扰物增殖下的鲁棒性"，**不是**"把代码收进知识库值不值"。后者的公平评法需要一批以 `.py` 为金标的题（留作阶段 3）。所以判决边界写清楚：不能说"扩容会让 RAG 变差"，只能说"扩容后原文档题的召回腰斩，且 hybrid 是唯一被实测验证过的抗稀释组件"。
- **阶段 2（扩库端到端 42 题，约 126 次调用）已备料未跑**：`run_scale_e2e.py` 首题即 `403 AccessDenied.Unpurchased`，8 个 chat 模型逐个探针（`evaluation/probe_models_v12.py`，每次 8 token）全拒，而**嵌入调用同一时刻仍然正常**。换公共 dashscope 端点复探，答复改成 `400 Access denied, please make sure your account is in good standing` ——**定位到账号级欠费/额度状态，不是工作区没授权该模型**（排障过程顺带修掉一个真 bug：`load_credentials` 里 `LLM_BASE_URL` 会被 `~/.bailian` 的 base_url 悄悄覆盖，现已改为环境变量优先）。付费调用实际成功 0 次，零浪费（预检已确认裸考臂 42/42 命中缓存）。
- **判词：主流程不动**（hybrid + k=4 + 现索引）。但"索引必须跟随文档重建"从口头经验升级为实测：**扩容不是免费的，每一份无关文档都在给全库检索交噪声税**；真要收代码进库，需要按文档类型先分域再检索，那是架构级改动，不是配置级。
- **v12 教训**：消融的对照臂要盯死"除了目标变量什么都别动"。我最初直接把 58 块旧快照和 387 块新索引对比，那 24 题的跌幅里混着"README 这几轮长高了"；补一个**零费的仅文档对照臂**才敢把账记在规模头上。顺带一条：新建索引时 md 块 56/76 命中嵌入缓存，说明缓存键（文本 md5）对增量语料天然友好——加文档不重付旧账。

## 工程化要点
- **凭证**：全从 `~/.bailian` 或环境变量读，仓库零明文（复用第9课教训）
- **缓存**：嵌入和 judge 结果落 `index/`（已 gitignore），重建索引、重跑评估零重复计费
- **切块**：按 `##` 标题切，超长段落按句边界二次切并保留 80 字重叠——v6 消融证明其价值在引用归因而非检索指标（检索层测不出差异）；v12 加 `chunk_code()`，代码按顶层 `def`/`class`/装饰器切、超长按行边界切且不做重叠
- **向量库**：千级块用 numpy 手写余弦即可，不引 chromadb/faiss，依赖最小化
- **测试**：18 个离线单测（散文切块/代码切块/存储/BM25 分词与打分/RRF 融合/子问题解析/数字核验器/端点优先级），不花一分钱 API
